The mod uses the dependency's shared scheduling pool and the JDK/common-pool networking primitives rather than feature-owned thread pools. Diagnostics should report feature queues and JVM thread states without inventing a global coroutine count.

Security-sensitive setup reuse is keyed by exact configured/imported key bytes, bounded, and must evict failures. It must never reuse authorization decisions, signature results, expired manifests, revoked devices/builds, challenge consumption or permission checks. The implementation currently issues short online leases and bounded offline grace separately from activation-code expiry; optimization must preserve the existing configured durations.

Current Cloudflare references checked before service review: [WebSocket hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/), [alarms](https://developers.cloudflare.com/durable-objects/api/alarms/) and [SQLite storage](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/). Hibernation avoids idle handler work, but required alarms still wake the object; replacing an alarm changes its deadline. SQL authority remains persistent and transactional.

Measured checks will be recorded separately after changes. Pure synthetic throughput, allocation and request/import/write counts do not establish Minecraft FPS, GPU performance, startup wall time, public-server latency or four-hour heap stability.

## Implemented changes and local evidence

The bounded setup caches hold at most 256 public keys, four private keys and four validated signing configurations. Failed imports/configurations are evicted; concurrent identical setup coalesces. Configuration values are captured before awaiting work, so a cache entry always belongs to the exact key bytes that were tested. Every lease still receives a real signature and signature verification; mutable account/device/build/session checks and all replay consumption remain uncached.

`node test/drm-cache.mjs --benchmark` runs the actual TypeScript DRM functions transpiled into Node 22.15.0 using WebCrypto, with counting wrappers. Five samples of 300 warm configuration-check / lease-sign / lease-verify cycles produced:

| Measurement | Before | After |
| --- | ---: | ---: |
| Median wall time | 595.339ms | 136.315ms |
| Key imports per sample | 1,200 | 0 |
| Sign calls per sample | 600 | 300 |
| Verify calls per sample | 600 | 300 |

The 300 remaining signs/verifies are the actual 300 leases. The removed 300 signs/verifies were repeated immutable configuration self-tests. The benchmark measures local setup/crypto work with instrumentation, not deployed Worker or Minecraft latency. Rotation, forged payloads, mutable-configuration capture, failure retry, concurrent imports and eviction tests pass.

The real Miniflare SQLite regression installs a temporary trigger after an authenticated connection: 50 `checkSession` calls forwarding the same observed ping timestamp produce zero telemetry writes; a newer timestamp from the current connection produces exactly one write. Older observations and a retired connection produce none. Authorization checks still execute for every call.

Client changes retain exact cache/provider/retry lifetimes. Idle wealth scans poll at most once per second and wake sooner for the existing freshness/retry deadline, explicit refresh/new friend, social roster/UUID revision, account identity, relay capability or disconnect. Native friend objects are compared to an immutable snapshot before client processing, preserving immediate UUID changes while avoiding repeated linear per-name lookups. Relay timeout sweeps allocate a callback snapshot only for expired/canceled requests; pending completions can add a new request safely. The party-policy cache removes expired records on insertion and caps historical keys at 1,024. Its existing 20s freshness remains unchanged.

The relay HTTP client is lazy until the first real connection. Auction parsing reuses two compiled UUID/style expressions instead of three compilations per valid listing (6,000 compilations for a 2,000-listing page become two process-lived expressions); response limits, parse rules, page pacing and stale-generation guards are unchanged. Chest slot/content references clear on container close, unrelated initialization, island changes and disconnect; floor knowledge remains available between chest menus within the same dungeon hub context.

Optional profiler scopes cover auction HTTP, friend API work, relay parsing and sends. Network-byte accounting allocates UTF-8 copies only while profiling is enabled; normal callbacks already have bounded serialized text/bytes. Cold diagnostics expose only queue/cache/job/socket counts and no credentials or packet bodies.

`npm run check` and the complete `npm test` passed after the service edits, including the existing HWID, cross-install transfer, launch session, revocation, anti-replay, signed Discord, private recovery, artifact, IRC and prompt regressions. Client checks are coordinated with the shared Java 25 build. No live deployment, Discord message or external API lookup was used for verification.
