# Community statistics sharing

Sharing is an account preference, independent of permission to run the Fabric mod. New accounts enable supported statistical contributions by default. Public RNG reports use `Anonymous` unless the user enables public names. Discord chat and cosmetics keep their own identity and continue when sharing is disabled.

The Community Sharing controls cover all statistics, dungeon statistics/profit, economy totals, RNG drops, activity/progress, leaderboard contributions, and public names. A contribution must satisfy both the global switch and its category; leaderboard contributions also require the leaderboard switch. Personal tracking and independent public API calculations remain local and available.

The client first reads authoritative account preferences, then saves explicit changes with a revision compare-and-swap. Contributions pause until preferences synchronize. An old device default or another account's pending enable edit cannot overwrite a saved account opt-out. An untouched fresh-device anonymous-name default also preserves an existing account's saved name choice; an explicit disabling edit remains effective. Existing Daily Digest `shareRng=false` and `publicRngName` values migrate once; their persisted paths remain available for migration. The unrelated, unused `gatherData` setting is not repurposed as consent.

Disabling a category deletes its stored cache publications and RNG reports, clears pending related upload grants, and suppresses historical delivery at the authoritative server. Linked Minecraft UUIDs inherit the Discord account preference. Unlinking snapshots the selected UUID's restrictive policy and monotonic suppression cutoffs before removing ownership, so anonymous fallback or later linking cannot restore enabled defaults; unrelated source associations keep their preferences and records. Third-party cache reports require consent from both the statistical subject and the contributor. Legacy wealth rows without contributor provenance are discarded on economy suppression. Re-enabling starts a new time window and does not upload or redistribute saved history. Changing public names from on to off removes prior named RNG reports. Privacy removal messages clear connected clients' community cache, with tombstones preventing delayed responses from restoring deleted records. Reconnecting reloads the RNG feed from the authoritative server; personal local history is retained.

Current contributions include public dungeon cache fields, public wealth totals, and newly detected supported RNG drops. New, locally observed completed dungeon runs contribute one run each; fully priced completed chest receipts and priced confirmed Kismet decreases contribute explicitly estimated profit. Unknown prices/costs do not create zero-valued profit samples. Own-account networth, purse and bank snapshots use the existing optional public API provider, with estimated provenance, bounded refreshes and no friend snapshot standing in for the player. Economy reports never contain item NBT, inventory contents, or API keys. Detailed Daily Digest task/progress and Dungeon Tracker archives stay local. There is no completed-task publisher, so that leaderboard metric remains unavailable rather than inventing progress.

The extensible contribution table accepts only declared metrics, finite values, complete recent observations, declared units, and source/verification labels. Client observations and estimates stay unverified or estimated. Accepted RNG reports add their leaderboard count at the server exactly once per author event; the client does not double-submit RNG counts. The all-time ledger retains observations until explicit suppression, with an explicit capacity error rather than silently deleting old months. Missing data, incomplete observations, fabricated placeholder values, and client claims of verified authority are rejected. Reconnection, migration and old journal history never replay contributions.

Checks cover default consent, authenticated account ownership, concurrent revision updates, linked-account preference inheritance, category/global deletion, historical cutoffs, source-tagged contribution validation, delayed client response suppression, and retention of personal history. These are offline fixtures with synthetic identities and no external messages or deployment.
